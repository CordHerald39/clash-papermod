## 迁移时先换客户端，再谈配置

把 Clash 电脑端迁到新 Mac，不能把旧磁盘上的应用包、服务残留和系统代理设置一次性拷过去。仓库写明配置与日志只保存在本地、不收集用户数据；功能列表另有 WebDav 配置备份和同步。同时，macOS 安装包按芯片拆分，且系统需为 macOS 11+。新机若芯片不同（Intel 换成 Apple，或相反），旧 dmg 架构直接失效。因此恢复顺序应是：在新机用官方 Release 的 Stable tag 安装对应 dmg → 再恢复配置 → 再处理服务与系统代理/TUN。

判断依据：发布页 Apple 芯片用 `aarch64.dmg`，Intel 用 `x64.dmg`。新机芯片未核清之前，不要恢复订阅或拷贝数据目录。旧机若曾用 AutoBuild 或已废弃 Alpha，新机日常使用应改回 Stable，避免把测试通道的缺陷一起迁走。

## 配置、服务、系统代理要分三项恢复

第一项是配置本身。优先用应用提供的 WebDav 备份在新机拉回；若没有 WebDav，只迁移本地配置与日志目录中的配置文件，不要连带拷贝旧服务进程。不同来源订阅或规则集共用缓存路径、DNS 覆写与 Merge/Script 的覆盖关系，在官方修复说明里被单独处理，说明配置目录不是“整夹复制即可”。迁完后应在新机重新拉取订阅，确认缓存路径按新机生成，而不是沿用旧机绝对路径。

第二项是服务模式与内核。v2.5.6 指出残留服务进程会导致内核无法启动，Sidecar 无法继续且难以修复；部分账户安装或修复服务时会因用户组解析失败而中断；用户目录在外置磁盘时服务可能拒绝启动内核。新机应在本机重新安装或修复服务，而不是把旧机服务状态当作用户数据迁移。开发说明里 Sidecar 与服务安装是不同启动路径，迁移后需要按新机实际选择，不能假设旧机的服务模式会自动存在。

第三项才是系统代理与 TUN。它们是系统级网络设置，不是应用文件夹的一部分。v2.5.7 写明：VPN 接管或开机网络未就绪时，服务模式内核可能起不来，TUN 不可用，系统代理状态读取会报错；手动 `ipconfig set` 改网卡后可能无法设置系统代理。v2.5.6 写明：服务模式内核意外停止后，系统代理仍可能指向失效端口。新机应等网络就绪、内核确认运行后，再打开系统代理或 TUN，并检查代理端口是否仍指向当前内核，而不是沿用旧机端口。

## 逐项失败时的回退

客户端架构或系统版本对不上：停在安装阶段，回到 Release 选 macOS 11+ 与正确芯片的 dmg，不要用旧机拷贝的 .app 凑合。配置恢复后内核仍拒启动：检查是否误拷了服务残留、用户组是否可解析、数据目录是否在外置磁盘，按该版本发布说明处理，而不是反复导入同一份订阅。系统代理或 TUN 在新机无效：先确认内核已运行，再清掉指向失效端口的旧代理，避免与其他 VPN 同时接管；不要把“迁机后不能上网”直接当成订阅失效。三项都通过后，迁移才算完成。
