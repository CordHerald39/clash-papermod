订阅更换域名之后，是否改自己保存的可信来源，不能凭“新域名也能打开”决定。HTTP 把“永久换 URI”和“临时换 URI”分成不同状态码：永久类要求把权威地址改到响应给出的新 URL；临时类则要求今后仍使用原来的 URI。可信来源记录应跟随这一语义，而不是跟随某一次碰巧成功的落点。

## 适用条件

适用于原订阅主机停用、改名或声明迁址，需要更新本地“以后该请求谁”的记录，同时避免把登录页、镜像或临时跳转写成新的权威来源。依据为 MDN 状态码说明（RFC 9110）；未列入的码可能是服务器自定义响应，不能当作标准迁址。不涉及具体客户端里的更新入口名称。

可信来源在这里指：你愿意长期用来发起 GET 的那个 URI 的方案与主机（authority）。GET 成功时资源在消息体中传输；若从未出现这一成功语义，就谈不上新来源已经可信任。

## 哪些响应允许改写长期来源

允许把记录改到新 URI 的，是永久重定向：

- 301：请求资源的 URL 已永久改变，新 URL 在响应中给出。应将可信来源更新为该新 URL，而不是继续把旧主机当权威。
- 308：资源现在永久位于 Location 头给出的另一 URI，语义同 301，且不得改变方法。更新记录时同时记下：新 URI、方法保持不变。若迁址过程被改成 POST，则不符合 308 对用户代理的要求，该次跟随结果不应直接当成已核验的新来源。

必须明确不要改写长期来源的：

- 302：URI 只是临时改变，今后还可能再变，客户端今后请求应使用原来的 URI。把 302 落点写入可信来源，等于丢掉规范要求保留的旧地址。
- 307：临时重定向且必须保持原方法，处理同 302：内容可以暂时从新主机取，记录里的权威地址不变。
- 303：只是让客户端用 GET 去另一 URI 取资源，常指向说明或登录页，不表示订阅域名完成迁移。
- 300：多种可选响应，无标准化自动选择，不能从中自动产生唯一新权威。
- 304：缓存未修改，不提供新域名。
- 203：元数据并非与源服务器完全相同，可能来自镜像或备份；除该特定用途外更推荐 200。镜像 203 不能单独证明域名迁移已完成。

305 已因安全问题弃用，306 不再使用，二者都不能作为迁址依据。

## 旧域名失效时如何改记录

若旧 URI 已不再提供资源，用客户端错误类判断是“改地址”还是“删记录”：

- 404：找不到资源；在浏览器中表示 URL 无法识别。若同时没有 301/308 给出新 URL，只能标“旧来源失效，尚无标准永久新地址”，不要凭猜测填写新域名。
- 410：内容已永久删除且无转发地址，客户端应清除缓存和链接。此时应删除该条可信来源，而不是改写成某个未在响应中给出的新主机。
- 421：请求打到了无法针对该 scheme 与 authority 组合产生响应的服务器。迁域后若方案或主机配错，应先核对自己记录的 scheme 与 authority，而不是继续追加路径。
- 401/403：未认证或已认证但无权限，说明的是访问控制，不是域名迁移完成。
- 451：因法律原因无法提供，不能用另一随意域名替换进可信列表。

服务器错误 500、502、504、503（暂时不可用，可能带 Retry-After，且暂时响应通常不应缓存）只说明当下取不到，不能证明域名已迁或未迁。

## 更新记录失败时的下一步

仅当链上出现 301 或 308，并且最终能对 Location 中的新 URI 做出 GET 且得到带消息体的成功响应时，才把可信来源改成该新 URI。若只有 302/307，保留原 URI 为权威，临时落点最多记为一次性取出位置。若 301/308 指向的新主机随即 401，来源可以更新，但须另注“新权威需要认证”，在未认证前不要宣称配置已可导入。出现 410 则删除记录；出现循环或 508 则本次迁址核验作废。对外同步记录时只写旧主机、新主机与状态码，不必公开完整订阅 URL。未列出的状态码保持“非标准，未采纳为迁址证据”。
