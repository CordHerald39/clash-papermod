更换 Clash 订阅凭据后，要单独验证「旧地址或旧令牌是否已不能取到资源」。验证看的是旧请求的 HTTP 状态码，而不是新订阅是否已经 200。MDN 指出 401 表示未认证，客户端必须先认证才能获得响应；若旧凭据已失效，旧请求常见结果就是 401。若旧请求仍是 2xx，则旧地址尚未停用。

## 适用条件

适用于已经启用新凭据、需要确认旧 URL 或旧令牌不能再下载订阅的场合。新地址自己还在 401 时，先处理新凭据，不能用来证明旧地址已停用。旧请求没有任何状态码时，只能说明这次没连上，不能证明资源已关闭。

## 验证步骤与判断依据

1. 对旧地址发起一次与当年相同的取订阅请求，只看状态码。判断依据：401 表示服务器要求认证且当前这份旧凭据未通过，符合「未认证即不可取」。
2. 同时识别其它「旧资源不可用」的完成态码。403 表示身份已知但无访问权，旧账号可能仍被识别却已无权限；404 表示找不到资源；410 表示内容已永久删除且无转发地址，客户端宜去掉缓存和链接。这些都可以作为「旧入口不再提供内容」的依据，但含义与 401 不同，应原样记录。
3. 若旧请求仍返回 200，说明资源仍被成功取出，旧地址未停用。若返回 301、302、307、308，还要看重定向目标：最终仍 200，则旧入口仍能转到可用内容；最终 401 或 410，再按最终码判断。
4. 不要把 407、511 当成旧订阅已作废：前者是代理要认证，后者是网络准入认证。也不要把 429、503 当成停用，它们分别是请求过多和服务未就绪，可能是临时状态。

## 失败时下一步

旧请求无状态码，改在同一网络条件下重试，直到出现三位码再下结论。旧请求 200 而业务上应已作废时，向提供者确认是否尚未撤销令牌或是否只换了文档未换资源。旧请求 401、新请求也 401，说明当前认证方式整体无效，先核对新凭据，不能解释为「旧的已停、新的已生效」。两次结果都记下脱敏 URL 与状态码，避免只保存新地址的成功结果。
