整理 Clash 电脑端安装包时，目的不是把下载文件夹清空了事，而是让每一份文件仍能对回官方发布页上的具体标签、平台和变体。Clash Verge Rev 要求到发布页面下载对应安装包，资源文件名里已经带有版本与架构信息。下面只说明整理目录时如何保住这些可追溯线索。

## 适用条件与判断依据

适用于已经从官方发布页取得安装包、准备归档或清理下载目录的情况。一份文件是否可追溯，可按三点判断：是否仍使用发布页给出的原始文件名；能否对应到发布标签（如 v2.5.7）；同一次发布里若提供了签名文件，是否与安装包成对保留。

官方仓库写明：请到发布页面下载对应安装包；支持 Windows（x64/x86）、Linux（x64/arm64）和 macOS 11+（intel/apple）。Windows 发行说明同时写明不再支持 Win7。版本类型上，Stable 为正式版、适合日常使用；AutoBuild 为滚动更新、可能存在缺陷；Alpha 已标为废弃。整理时应把正式版与滚动更新版分开放，避免日后无法判断当时用的是哪一类构建。

同一标签下还有多种包。Windows 推荐“正常版本”，另有体积较大的内置 Webview2 版，说明仅在企业版系统或无法安装 Webview2 时使用。macOS 分为 Apple M 芯片与 Intel 芯片的 dmg。Linux 分为 DEB（Debian 系，使用 apt ./路径 安装）与 RPM（Redhat 系，使用 dnf ./路径 安装），并再分 64 位、ARM64、ARMv7。文件名中的 x64、arm64、aarch64、amd64、armhf、fixed_webview2、setup.exe、dmg、deb、rpm 都是追溯字段，不能改成没有版本、没有架构的泛称。

## 整理目录时如何保留原始文件名与签名

不要把安装包改名为 Clash.exe、verge-latest.dmg 这类名字。应保留发布页上的完整名称，例如 Clash.Verge_2.5.7_x64-setup.exe、Clash.Verge_2.5.7_aarch64.dmg、Clash.Verge_2.5.7_amd64.deb。版本号已写在文件名里，目录可以按发布标签再建一层，例如以 v2.5.7 为文件夹名，把该次发布下载的安装包与对应 .sig 放在一起。

若资源列表中存在同名安装包的 .sig，应与安装包同目录、同批次保留，不要只留 exe、dmg、deb 或 rpm 而丢掉签名文件。同一版本若同时下载了“正常版本”和“内置 Webview2 版”，必须靠文件名中的 fixed_webview2 区分。Linux 还应按包格式分开：deb 与 rpm 的安装命令不同，混放且改名后难以判断该用 apt 还是 dnf。

清理浏览器默认下载位置前，先确认归档副本的文件名与该次发布的 assets 一致，再删除重复项。不要只保留“最新一个”却改掉文件名。发布页会同时列出历史版本（如 v2.5.6、v2.5.5），本地一旦丢失原始名，回滚或核对就失去对照。若一并保存了 latest.json，可放在对应版本目录作辅助记录，但不能替代带版本号的安装包本身。

## 对不上版本或文件缺失时的下一步

若已经改名，或只剩一个不知版本的安装包，不要凭体积猜测。回到官方发布页，用仍记得的大致时间或需求对照 tag_name，再按系统与架构重新下载原始文件名的安装包，并补齐同版本的 .sig（若该资源提供）。Windows 需确认不是 Win7，并区分是否需要内置 Webview2 版。macOS 按芯片选择 aarch64 或 x64 的 dmg。Linux 按发行版选择 deb 或 rpm，再选择 amd64、arm64 或 armhf。

若多种架构混在同一文件夹且无法辨认，以文件名中的架构字段为准；文件名已丢失则只能从对应 tag 的资源列表重新下载。若误把 AutoBuild 与 Stable 放在一起，按发布页的版本类型说明分开存放，日常使用应对应 Stable 的 Release。安装或重装仍异常时，以官方仓库指向的文档与常见问题说明为准，而不是继续改本地文件名。需要核对历史构建时，应以发布页上仍保留的 tag 与完整文件名为准重新拉取。
