策略组重新加载后，若要把日常固定使用的出站再次选中，应当把该选择写进配置，而不是寻找本页没有记载的界面记忆或外部存档。手册在代理组通用字段中给出 default-selected，含义是默认选择的节点；该项为空，或者设置的节点名不存在时，将默认选择组中第一个节点。因此所谓方便恢复，在官方资料里能落地的部分，就是把常用名称写成默认项，并保证该名称在引入和筛选之后仍然存在。下面只使用该页已经出现的 name、type、proxies、use、include 类开关、筛选和 empty-fallback，说明适用条件、操作顺序和失败时如何判断。

## 适用条件

本做法适用于你可以直接编辑 proxy-groups，并且目标策略组已经通过 proxies 引入出站代理或其他策略组，或通过 use 引入代理集合的场景。name 是必须项，策略组的名字如有特殊符号，应当使用引号将其包裹，否则名称本身都无法稳定引用，更谈不上恢复选择。type 是必须项。当组为空时，empty-fallback 指定回退 proxy，默认为 COMPATIBLE；手册注明这里不支持填写代理组，只支持填写 proxy 名称。判断能不能靠默认项恢复的依据是：你要记住的对象必须是最终成员列表里的出站名称。若名称指向另一个策略组，可以写在 proxies 里作为成员，但不能写进 empty-fallback。

写入前必须预判筛选结果。filter 筛选满足关键词或正则表达式的节点，exclude-filter 做排除，二者都可以用反引号区分多个正则，并且仅作用于引入代理集合以及引入所有出站代理。exclude-type 不支持正则表达式，通过竖线分割，根据节点类型排除，仅排除引入的出站代理，类型比对无视大小写。include-all、include-all-proxies、include-all-providers 会引入相应集合并按名称排序，引入不包含策略组。若常用节点会被排除、未通过筛选，或只存在于尚未引入的来源中，默认项在运行时等于节点名不存在，行为将变成选择第一个节点。

## 写入步骤

第一步，写好 name，后续规则或其他策略组引用时必须使用同一字符串，有特殊符号则加引号。第二步，用 proxies 列出候选出站或其他策略组，需要集合时再用 use。务必理解顺序：默认项为空或不存在时选择组中第一个节点，所以列表顺序是恢复失败时的回退依据，不能随意打乱后再假设仍落在常用节点。第三步，把 default-selected 设为常用节点名，并核对该名称在筛选之后仍在列表中。第四步，若打开 include-all 或另外两个 include 开关，成员将按名称排序，原先写在最前面的项可能不再是第一，必须重新确认默认名和第一项分别是谁。第五步，仅当可能出现空组时才配置 empty-fallback，且只填 proxy 名称，不要填策略组。第六步，不要用 hidden 或 icon 冒充记忆：前者让 API 返回隐藏状态，后者把字符串交给使用 API 的前端适配，都与默认选择无关。第七步，不要在代理组上继续写 interface-name 或 routing-mark，这两项已弃用，应写到代理节点，优先级为代理节点大于代理策略大于全局。文档示例中 type 为 select，与配置指定默认成员、组内仍可再选的场景一致。url、interval、timeout、expected-status 属于健康检查，不能用来记录选择。

## 失败时下一步

重载后当前成员不是常用节点时，按手册含义判断，而不是改无关项。首先检查 default-selected 是否留空、是否与节点名逐字一致、该节点是否被 filter、exclude-filter 或 exclude-type 去掉。若判定为名称不存在，下一步应列出引入并筛选后的成员，看谁成为第一个节点，那才是实际回退目标。若整个组为空，检查 empty-fallback 是否误填策略组，或是否指向不存在的 proxy。若常用节点只出现在某一集合，确认 use 与 include-all-providers 是否生效，以及 filter 是否把它滤掉。disable-udp 只关闭该策略组 UDP，与选择记忆无关。核对上述字段后仍无法对应，回到 proxies、use 和三个 include 开关检查引入源是否变化，到此为止，不要增加本页未给出的恢复步骤。
